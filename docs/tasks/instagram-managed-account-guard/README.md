# Тестовая защита Instagram от ответов между нашими аккаунтами

Ветка: `test/instagram-managed-account-guard`, создана от `main`.

Пользователь согласовал изменение прежнего правила: ручные сообщения между
управляемыми аккаунтами тоже не получают AI-ответ. Вместо этого отправляется
служебное уведомление с предложением обратиться к разработчику.

## Поведение

- `message.is_echo === true` и `entry.id === sender.id` пропускаются без отправки:
  это исходящие события; отвечать на них нельзя.
- Входящие сообщения самому себе (`sender.id === recipient.id`) и от наших
  аккаунтов получают служебное уведомление без AI и записи в историю AI.
- Полученное служебное уведомление всегда пропускается без ответа. Это условие
  не зависит от `mid`, порядка событий или состояния процесса и действует после
  перезапуска. Текст уведомления должен оставаться одинаковым на всех экземплярах.
- Для обычного клиента сохраняются прежние AI-ответы и реакции сердцем.
- Тестовый обработчик использует ту же защиту, но возвращает текст без отправки.

## Идентификаторы и конфигурация

Перед запуском задайте `INSTAGRAM_MANAGED_ACCOUNTS` в окружении процесса либо
в игнорируемом `.env`, который загружает Nest. Например, с вымышленными значениями:

```dotenv
INSTAGRAM_MANAGED_ACCOUNTS='{"900000001":"sample_lodge","900000002":"sample_waves","900000003":"sample_club","900000004":"sample_test"}'
```

Замените примеры на ID профессиональных аккаунтов и актуальные username.
Включите **все** управляемые аккаунты, в том числе с отсутствующим или истёкшим
access token. Список независим от `services.instagram.accessTokens`; встроенного
списка и резервных значений нет. При переименовании аккаунта обновите env.
Не добавляйте реальные значения в Git; перед записью проверьте
`git ls-files -- .env` (вывод должен быть пустым) и `git check-ignore .env`.

Формат: непустой JSON-объект, каждый ключ состоит только из цифр, каждое значение
является непустой строкой после удаления крайних пробелов. Username приводятся к
нижнему регистру. Ошибка любой записи делает недействительным весь список.
Фабрика конфигурации разбирает env после загрузки `.env` и передаёт результат
через `services.instagram.managedAccounts`. Другие файлы конфигурации не могут
предоставить резервный список при отсутствии этой env-переменной.

При отсутствии или некорректном значении **все автоматические Instagram-ответы**,
включая служебное уведомление и реакции сердцем, отключены. В логе появляется
диагностика `INSTAGRAM_MANAGED_ACCOUNTS is missing or invalid` без значений env и
токенов. Остальные каналы продолжают работать. Исправьте env и перезапустите
процесс, чтобы фабрика загрузила новый список.

`sender.id` в чужом входящем вебхуке отличается от ID профессионального аккаунта.
Поэтому перед AI выполняется GET
`https://graph.instagram.com/v23.0/{sender.id}?fields=username` с токеном
получившего вебхук аккаунта; username сравнивается с реестром без учёта регистра.
Read-only проверка ранее подтвердила разрешение обоих scoped ID текущего цикла
в username соответствующих управляемых аккаунтов; реальные значения здесь не публикуются.

## Ограничения тестовой версии

- Профиль запрашивается для каждого входящего сообщения неизвестного отправителя;
  это добавляет сетевой запрос и использует квоту Meta.
- При недоступности профиля, отсутствии username или токена сообщение пропускается
  без ответа, в том числе от обычного клиента. Ошибки авторизации передаются в
  существующий механизм уведомления разработчика.
- Повторная доставка исходного сообщения может вызвать повторное служебное
  уведомление; каждое уведомление завершается без обратного ответа и не вызывает AI.
- Предполагается, что все участвующие экземпляры используют эту защиту и одинаковый
  текст уведомления. Продовая версия без защиты может отвечать на уведомления.
- Защита не распространяется на сторонние боты и не заменяет общий лимит ответов.

## Проверка перед серверным тестом

Задать env со всеми управляемыми аккаунтами на каждом экземпляре. Проверить
получение профиля с токеном каждого активного аккаунта. Затем на
экземплярах с этой веткой проверить клиента, ручной обмен аккаунт A→B и обратно,
echo и доставку уведомления после перезапуска. В межаккаунтных сценариях не должно
быть вызовов AI; на уведомление не должно быть отправки ответа.

Эта ветка не развёрнута на сервере. Прежний план
`docs/tasks/instagram-self-reply-guard/plan.md` описывает другое бизнес-правило;
его отклонённая схема сопоставления `message_id` не используется.
